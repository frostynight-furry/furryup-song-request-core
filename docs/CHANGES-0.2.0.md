# 0.2.0：推荐续播与点歌匹配修复

这次把 FurryUP Studio 本地验证过的调度规则整理进独立组件：QQ、网易云个人推荐逐首轮换；收到点歌后，播完当前推荐，按顺序处理观众队列；队列空了继续下一平台。播放器、账号、音源接口和直播间接入由宿主提供，核心仍无运行时第三方依赖。

## 相比 0.1.0

| 行为 | 0.1.0 | 0.2.0 |
| --- | --- | --- |
| 没人点歌 | 队列空后停止 | 可开启个人推荐续播 |
| 两个平台推荐 | 无调度接口 | QQ / 网易云逐首轮换，失效时尝试另一家 |
| 推荐中收到点歌 | 不适用 | 当前曲播完后依次处理点歌 |
| 点歌清空 | 等待下一次点歌 | 恢复保存的推荐轮换位置 |
| 空格分隔的歌手匹配 | 完整歌手与合唱成员可能同分 | 完整歌手优先，手动搜索仍列出各版本 |
| 设置保存 | 点歌规则、曲库 | 增加独立推荐开关及下一平台，不改原配置格式 |

新增调度处理了获取超时、取消、暂停、紧急停止、来源变更、迟到结果、近期去重和失败限速。已排队的观众请求具有优先权，推荐不占观众队列名额。

## 与之前开源参考项目的关系

本引擎从 FurryUP Studio 的原创通用代码拆出，以 MIT 开源，并非 Yumi 或 AwooMusicBot 的源码分支。之前对照过 [Yumi Player](https://github.com/c-basalt/yumi-player) 的请求过程反馈，以及 [AwooMusicBot](https://github.com/Enkianssus/AwooMusicBot) 的队列撤回、状态同步和 OBS 展示思路；它们的实现代码和播放器连接器没有复制进本组件。

独立引擎已有的请求解析、保守匹配、串行队列、礼物资格、同曲换源、下一首预检和阶段记录，以及这次增加的推荐调度，均由本项目维护。FUS 宿主的真实音乐服务继续使用已有 QQ / 网易云 API 依赖及自己的授权、播放适配；这不等于重写了两家的音乐接口，也不代表已适配汽水音乐。

- 上述宿主测试为**静音 8 倍速实际解码**，没有跳进度或伪造结束事件；它不能替代正常速度人工听音、真实直播间连续弹幕或 OBS 收音验收，也不能证明所有账号和曲目都有完整播放权限。
- 公开仓库仅包含源码、合成测试和文档，不附带真实账号、Cookie、音频、用户配置、完整桌面应用或测试截图。上传源码不会自动更新 FUS 安装器或组件分发渠道。
